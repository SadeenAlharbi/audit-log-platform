# دليل اختبار القبول من الواجهة

يشرح هذا الدليل كيف يُختبر كل متطلب في الخطة (الإصدار 1.1) يدويًا قبل التسليم: الخطوات، والنتيجة المتوقعة، ورقم البند في الخطة. الاختبارات الآلية (211 اختبارًا) تغطي البنود نفسها؛ هذا الدليل للتأكد منها بالعين.

أغلب الاختبارات من لوحة التحكم. بنود حماية الـ API (§6 و§7) تحتاج إرسال طلبات من الطرفية بـ `curl`، ثم التحقق من نتيجتها في اللوحة.

```bash

```

**الحسابات التجريبية** (كلمة المرور لكلها `Demo!Passw0rd#2026`، أو قيمة `DEMO_PASSWORD` في `.env`):

| الحساب | الدور | يرى |
|---|---|---|

| `auditor@demo.test` | Platform Auditor | سجلات كل المشاريع، قراءة فقط |

## 5. حماية الـ API (§6، §7)

جهّز في الطرفية مفتاح «إرسال» من الخطوة 3.2 ومعرّف المشروع:

```bash
KEY='الصق المفتاح هنا'
P='المعرّف (slug)'
NOW=$(date -u +%Y-%m-%dT%H:%M:%SZ)
API=http://localhost:8080/api/v1
send() { curl -s -w '  [%{http_code}]\n' -X POST "$API/logs" -H "Authorization: Bearer $KEY" -H "X-Project: $P" -H 'Content-Type: application/json' -d "$1"; }
```

**5.1 الاستلام والرد 202**
```bash
send '{"external_id":"t-1","event":"order.paid","action":"update","occurred_at":"'$NOW'","subject":{"type":"order","id":"1"},"old_values":{"status":"pending"},"new_values":{"status":"paid"}}'
```
- ✅ المتوقع: `[202]` مع `uid`، والسجل يظهر في اللوحة خلال ثوانٍ.

**5.2 منع التكرار (Idempotency)**
- أعد الأمر نفسه.
- ✅ المتوقع: `[409]` بالخطأ `duplicate` و`uid` السجل الأصلي، ولا سجل جديد في اللوحة.

**5.3 التحقق من الحقول**
```bash
send '{"external_id":"t-2","event":"x.y","action":"create","occurred_at":"'$NOW'","foo":1}'
```
- ✅ المتوقع: `[422]` بالخطأ `validation`، لأن الحقل غير معرّف.

**5.4 المصادقة والمحاولات المرفوضة**
```bash
KEY=wrong send '{}'
```
- ✅ المتوقع: `[401]` بالخطأ `unauthorized`.
- أعده بمفتاح ملغى من 3.5.
- ✅ المتوقع: `[401]`.
- ادخل بحساب `security@demo.test`: **الأمان ← المحاولات المرفوضة**.
- ✅ المتوقع: المحاولات بالسبب (مفتاح غير صحيح، مفتاح ملغى) والـ IP والوقت.

**5.5 قائمة الـ IP**
- على المفتاح: **IPs المسموحة**، وضع `10.9.9.9`، ثم أعد 5.1 بـ external_id جديد.
- ✅ المتوقع: `[403]`، وسبب «عنوان IP غير مسموح» في المحاولات المرفوضة.
- أزل القائمة بعد الاختبار.

**5.6 توقيع HMAC**
- أنشئ مفتاحًا مع **توقيع HMAC إلزامي**، وأرسل به بدون `X-Signature`.
- ✅ المتوقع: `[401]`، وسبب «بدون توقيع» في المحاولات المرفوضة.
- الإرسال الموقّع: أمثلة جاهزة في `docs/integration-guide.md`، وزر السجل التجريبي (3.4) يوقّع تلقائيًا.

**5.7 حد الحجم 1MB**
```bash
python3 -c "import json,datetime;print(json.dumps({'external_id':'big','event':'x.y','action':'create','occurred_at':'$NOW','metadata':{'b':'a'*1100000}}))" > /tmp/big.json
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/logs" -H "Authorization: Bearer $KEY" -H "X-Project: $P" -H 'Content-Type: application/json' --data @/tmp/big.json
```
- ✅ المتوقع: `413` بالخطأ `payload_too_large`.

**5.8 إخفاء بيانات الدخول قبل التخزين**
```bash
send '{"external_id":"t-3","event":"user.updated","action":"update","occurred_at":"'$NOW'","new_values":{"password":"S3cret!","card_number":"4111111111111111","name":"Ali"}}'
```
- افتح السجل في اللوحة.
- ✅ المتوقع: `password` و`card_number` قيمتهما `[REDACTED]` حتى لـ admin، لأنها حُذفت قبل التخزين، و`name` كما هو.

**5.9 الدفعات (batch)**
```bash
curl -s -X POST "$API/logs/batch" -H "Authorization: Bearer $KEY" -H "X-Project: $P" -H 'Content-Type: application/json' \
  -d '{"logs":[{"external_id":"b-1","event":"a.b","action":"create","occurred_at":"'$NOW'"},{"external_id":"b-2","event":"a.b","action":"create","occurred_at":"'$NOW'"}]}'
```
- ✅ المتوقع: `202` مع `batch_uid` و`uid` لكل سجل، والسجلان في اللوحة.

**5.10 الاستعلام بمفتاح «استعلام»**
```bash
RKEY='مفتاح الاستعلام من 3.3'
curl -s "$API/logs?event=order.paid&per_page=5" -H "Authorization: Bearer $RKEY" -H "X-Project: $P"
```
- ✅ المتوقع: سجلات هذا المشروع فقط، مع مؤشر الصفحة التالية (`next_cursor`).
- استعلم بمفتاح «إرسال».
- ✅ المتوقع: `403` بالخطأ `forbidden`.

**5.11 لا تعديل ولا حذف**
```bash
curl -s -o /dev/null -w '%{http_code}\n' -X DELETE "$API/logs/01JABCDEF0123456789ABCDEFG" -H "Authorization: Bearer $KEY" -H "X-Project: $P"
```
- ✅ المتوقع: `405` بالخطأ `method_not_allowed`.

**5.12 Rate limit**
- ضع `AUDIT_API_RATE_LIMIT=5` في `.env`، ثم `docker compose up -d app`.
- أرسل 7 طلبات متتالية.
- ✅ المتوقع: بعد الخامس `[429]` بالخطأ `rate_limited`.
- أعد القيمة (احذف السطر) ثم `docker compose up -d app`.

**5.13 الصحة والتوثيق**
- افتح http://localhost:8080/api/v1/health.
- ✅ المتوقع: `"status":"ok"`، وحالة كل فحص `ok`.

- ✅ المتوقع: توثيق OpenAPI لكل المسارات.

## 6. الصلاحيات (§13)

**6.1 كل دور يرى ما يُسمح له فقط**

ادخل بكل حساب وتحقق:

| الحساب | يجب أن يرى | يجب ألا يرى |
|---|---|---|
| auditor | سجلات المشاريع الأربعة، والتصدير | أزرار الإنشاء والتعديل، والمستخدمين، والنسخ الاحتياطي |
| security | المحاولات المرفوضة، والمفاتيح وقوائم الـ IP | محتوى السجلات، والمستخدمين |
| owner | مشروع الموارد البشرية: سجلاته ومفاتيحه وأعضاؤه | أي مشروع آخر في الجداول أو الفلاتر أو التصدير |
| viewer | سجلات شؤون الطلاب وتصديرها | المفاتيح، والأعضاء، وأي مشروع آخر |

- جرّب كتابة رابط مشروع آخر مباشرة في المتصفح بحساب owner (انسخه من حساب admin).
- ✅ المتوقع: 404 أو 403.

**6.2 الأدوار المخصصة**
- **الإدارة ← الأدوار والصلاحيات**: أنشئ دورًا على مستوى المنصة بصلاحية `logs.view_sensitive` فقط، وأسنده لـ auditor.
- ✅ المتوقع: auditor يرى الآن الـ IBAN كاملًا.

- ✅ المتوقع: ينتهي بلا `ERROR` ويطبع مسار التقرير (`Report: storage/app/backup-spool/reports/...`). انسخ خلاصته إلى `docs/reports/` كما في `offsite-drill-2026-11-16.md`.

**9.6 الاحتفاظ والحذف**
- نفّذ `docker compose exec app php artisan audit:prune --dry-run`.
- ✅ المتوقع: ما سيُحذف لكل مشروع حسب مدة احتفاظه. لا يُحذف شيء قبل أرشفته ومرور فترة السماح (7 أيام).
